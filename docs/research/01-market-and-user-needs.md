# CAD 模型查看器竞品与用户诉求调研

**调研日期：** 2026-07-18  
**范围：** 面向 STEP/IGES/装配体检查的桌面或 Web 查看器，不把参数化建模、CAM
或 CAE 求解器当作查看器的必选范围。

## 结论先行

用户购买的不是“一个能把三角形画出来的窗口”，而是一个低风险的检查工作台：

1. 文件能打开，单位、结构、颜色、方向和几何不悄悄改变。
2. 从打开到可操作的首屏很快，大装配仍然能流畅旋转、选择和隐藏零件。
3. 能回答工程问题：这个零件是什么、尺寸是多少、干涉在哪里、剖面是否正确、
   PMI/备注是什么。
4. 结果能被复核和沟通：测量、截面、标注、截图、报告和版本对比都要可重现。
5. 不需要购买完整 CAD、注册云账号或上传敏感模型。

Cadly 目前已经有较好的基础：Qt 与 OpenGL 的宿主边界、独立的 scene DTO、STEP/IGES
XCAF 导入、装配树、PBR 试验渲染、异步导入、诊断条和多文档标签页。当前最大的产品
缺口不是再增加一个视图按钮，而是“选择/测量/截面/可信导入”闭环，以及大装配的首帧
和交互性能。

## 必须功能分级

### P0：发布前必须可信

这些能力缺失时，查看器会被认为“不可靠”，而不是“功能少”。

| 能力 | 验收标准 | 当前状态 |
| --- | --- | --- |
| 格式和版本 | STEP AP203/AP214/AP242、IGES；扩展名错误时支持内容探测；报告格式/版本 | 只有 STEP/IGES 扩展名选择；没有内容探测、P21 UI 入口，也没有格式诊断 |
| 导入进度与取消 | 读文件、Transfer、网格、抽取都能显示阶段；取消后线程在可预测时间退出 | 有 QtConcurrent 和阶段回调，但 OCCT Transfer/批量网格阶段没有可取消进度 |
| 单位可信 | 显示文件单位、场景单位、转换比例；测量结果带单位和精度 | STEP 单位是 best-effort，IGES 固定写成 mm；测量尚未实现 |
| 结构/颜色/名称 | 装配层级、实例变换、零件名、层、颜色不丢；相同原型可不同实例样式 | 树和颜色基础已在；layer、材料、实例颜色仍不完整 |
| 导入诊断 | invalid shape、未网格化面、降级路径、耗时、三角形和内存均可见 | 有 summary/timings/diagnostics，是优势；缺少 shape validation 和失败面定位 |
| 导航 | 轨道球/旋转、平移、滚轮/触控板缩放、Fit、标准视图、正交/透视 | 基础导航齐全；左键选择和“旋转到光标下的面”未完成 |
| 选择 | 零件、面、边、实例选择；树与视口双向同步；选择高亮 | `IRenderer::pick` 仍是 stub，`Node::selected` 没有消费 |
| 隐藏/隔离 | 单个节点、子树、反选、Solo 后 Fit Selection；状态可恢复 | 眼睛和 Solo 已有；不可对选中项执行 Fit/measure，因为选择未完成 |
| 大装配交互 | 首屏渐进出现，旋转不因首帧 GPU 上传卡住；内存/三角形可预估 | scene 资源在 paintGL 懒上传，且每个 face 一个 draw call |
| 安全与离线 | 默认不上传文件；路径/错误不泄露到第三方；可关闭遥测 | 当前为本地程序，符合方向；需要在文档中明确承诺 |

### P1：让工程评审真正可用

- 距离、角度、半径/直径、最短距离、连续测量；捕捉顶点/边/圆柱轴，显示公差和
  单位，支持测量列表、复制和截图。
- 任意剖切平面、盒裁剪和多平面；截面封口、剖面填充/线型、反向和透明度；截面与
  测量结果可保存。
- 爆炸视图、按层/材料/属性过滤、BOM/零件计数、搜索命中定位、反向查找父组件。
- PMI/注释/基准/GD&T 的可见性、选择和属性查看；不理解的语义要明确标成“只读图形”。
- 修订对比：重叠、差异颜色、树差异、仅显示变化项；结果可导出为 HTML/PDF/PNG。
- 轻量化：按屏幕误差的 LOD、隐藏分支不网格化、重复实例 GPU instancing、缓存。
- 导出/分享：glTF/GLB、STL/OBJ、带相机和标注的截图或离线审阅包；保持原始文件不变。

### P2：形成生态和商业化能力

- 断点续传/流式云查看、团队审阅、评论和权限；必须保留本地脱机路径。
- 插件和脚本（Python 或稳定 C API）、批处理导入、CI 格式回归测试。
- 质量分析：壁厚、间隙、拔模、干涉/碰撞、质量属性和包络；这些应依赖明确的几何
  算法许可证，不应伪装成简单可视化。

## 真实用户痛点

### 文件打开了，但用户不敢相信

常见失败不是进程崩溃，而是单位、实例变换、颜色、隐藏状态、曲面方向或小面在翻译
中改变。用户通常拿查看器截图去做采购或质量判断，所以“导入成功”必须包含可见的
诊断和单位信息。建议首屏固定显示：`格式 / 文件单位 -> 场景单位 / shape 数 / 未网格化面 /
三角形 / 导入阶段耗时`，并允许点击诊断定位树节点。

### 大模型等很久，等到后还不流畅

用户区分“可看到第一张图”和“完整可选/可测量”。应先显示低精度可见部分，再后台补全
细节，且状态写成“预览 / 完整 / 失败面”。当前代码把 GPU VBO 上传放在第一帧，等效于把
最后一段导入成本转移到了 UI 线程；这会破坏“导入已完成”的感受。

### 视图功能多，但找不到下一步

CAD 用户的动词是“选中、隐藏、测量、剖切、对比、标记”，不是“切换材质”。将工具按任务
分为 **Inspect（选择/属性/测量）**、**Section（剖切/透明/爆炸）**、**Communicate（标注/截图/
报告）**，把高级渲染放到 Display/Appearance，能降低学习成本。现有 Graphite shell 的
固定模型树、Inspector、Diagnostics 分区是合理方向，可继续以这三个任务流收敛入口。

### 云便利与 IP 安全冲突

Autodesk Viewer 等 Web 产品的便利来自上传和分享；制造企业、军工和供应商常常不能上传
源 CAD。产品定位应明确“本地优先、分享的是审阅包而不是源文件”，云协同作为可选插件。

### 测量和标注结果难以复核

一张截图不说明捕捉到哪条边、使用什么单位或模型版本。每个结果应保存 `source file hash /
node id / face id / unit / tolerance / camera`，显示时能回到几何位置。这样既解决用户痛点，
也迫使选择 ID 和场景 provenance 设计正确。

## Cadly 的产品取舍建议

### 第一条主线：可信检查工作台

优先完成以下闭环，再扩格式或渲染预设：

```text
打开 -> 阶段进度/取消 -> 诊断与单位确认 -> 树/视口选择
     -> 隐藏/隔离/Fit Selection -> 测量或剖切
     -> 保存审阅状态/截图/报告
```

### 推荐版本顺序

1. **Inspection MVP：** 选择 ID、树/视口同步、隐藏/隔离、Fit Selection、距离/半径测量、
   剖切平面、可信单位和失败面诊断。
2. **Large Assembly：** GPU/CPU 分阶段性能、预览 LOD、缓存、实例化和按需网格化；对 231 MB
   夹具模型把“可交互首屏”作为独立指标。
3. **Review Pack：** 标注、截图、JSON/HTML/PDF 报告、版本对比和离线审阅包。
4. **Format/PMI：** AP242 PMI、JT 或目标客户所需原生格式，以真实客户样本建立回归集。
5. **Appearance：** 在上述能力稳定后提供 Clay、Painted Metal、Aluminum、Rubber 等可解释预设，
   不把“更亮的银色”当作全部视觉价值。

## 建议的可量化产品指标

不要用单一“导入耗时”做 KPI，至少记录：

| 指标 | 建议定义 |
| --- | --- |
| TTFP | 从点击打开到第一帧可旋转的时间；预览和完整模型分别记录 |
| TTI | 树、选择、隐藏、Fit、测量都可用的时间 |
| 取消延迟 | 用户点击取消到 worker 结束的 P50/P95 |
| 可信度 | 解析/拓扑/颜色/单位/PMI 回归用例通过率 |
| 交互 | 典型视角下 GPU frame time P50/P95，首帧上传不算稳定帧率 |
| 内存 | 峰值 RSS、CPU mesh、GPU buffer、每百万三角形占用 |
| 结果 | 测量误差、剖面闭合率、失败面可定位率 |

## 资料与证据等级

- 产品能力：以上官方产品入口和公开手册；许可证、格式矩阵和平台支持需在采购时按
  具体版本复核。
- 用户痛点：由上述产品共同暴露的检查工作流、制造/供应链常见约束归纳，不把单一论坛
  帖子当作统计样本。
- Cadly 当前事实：见 [代码架构审查](04-code-architecture-review.md) 和
  [导入性能报告](02-import-performance-occt-vs-commercial.md)，均以当前工作树与实测为准。
- 性能承诺：商业厂商通常不发布可复现的同模型、同精度、同硬件数据；本调研不提供未经
  供应商或本地 A/B 验证的“快 X 倍”结论。
